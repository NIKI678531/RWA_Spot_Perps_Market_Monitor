# 结论固化为不可变的 edition

Live 数据每小时变一次。当两个人在会上引用「今天早上的数字」时，他们引用的可能是两组不同的数，
而且谁都没有说错——页面确实是那样显示过的。

一个用于产品立项和管理层汇报的系统，必须能让一句结论在几周后仍然指向同一批数字。
把这个责任交给「导出一份 Excel 存起来」是不够的：Excel 里的数字和线上页面会立刻分叉，
而分叉之后没有任何机制能判断哪一份是对的。

决定：所有对外结论都挂在 **edition** 上。

- `LIVE`：每小时刷新，页面常驻 snapshot 时间、数据年龄、下次刷新与部分源延迟。工作用。
- `MORNING`（09:00 HKT）与 `AFTERNOON`（17:00 HKT）：**冻结，一次写定，永不修改**。引用用。

迟到或更正的数据不修改冻结版，而是生成带修订原因与前后差异的 `v2` / `v3`，
被取代的版本仍然可读。`as_of`（数据截止）与 `generated_at`（生成时刻）分别展示。

## Consequences

- `edition` 表与 `fact_*` 一样是只追加的。代码里没有更新已冻结 edition 的路径，
  想改只能新增修订版——这是刻意让「悄悄改掉一个数」在实现上不可行。
- 页面 URL、导出和分享链接都固定 `edition` + `as_of`。切换 edition 保留其它仍然合法的筛选，
  因为筛选条件在两个版本之间通常仍然成立，而时间点不成立。
- 冻结任务失败必须告警且不得静默顺延。一个缺失的 09:00 版本比一个晚到的 09:00 版本更容易被发现，
  而一个内容错误的 09:00 版本最难被发现。
- 报告从冻结版生成而非从 Live 生成，因此报告与页面永远指向同一批数字。
- 代价：存储成本随版本数线性增长，且「今天到底看哪个版本」成了用户要理解的新概念。
  换来的是任何一句已发布的结论都能被复现——这个系统的产出会进入发行决策，
  不可复现的结论在那种场合等于没有结论。
