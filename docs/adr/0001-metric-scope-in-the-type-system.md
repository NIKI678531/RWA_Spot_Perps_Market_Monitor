# 口径进入类型系统

代币化 RWA 的五类指标（现货市值、现货成交、DEX 流动性、永续成交、永续 OI）都以 USD 计价，
因此把它们加起来在语法上完全合法、在语义上完全错误，而且结果看起来很像一个可信的总量。
源工作簿靠批注约束这件事（「任何汇总页都只能并列，不得相加」）——批注活不过一次重构。

决定：口径成为类型的一部分。每个金额是 `ScopedValue(amount, scope, verified)`，唯一的聚合入口是
`safe_sum()`，跨 `MetricScope` 求和抛 `MetricScopeViolation` 而非告警。
`RATIO` 维度的指标（份额、换手率、买卖比、滑点、funding）连同口径内求和也一并禁止，必须走
`weighted_avg()` 并显式给出权重口径。图表侧由 `assert_same_axis()` 拒绝 STOCK 与 FLOW 共用 Y 轴。

## Considered Options

- **代码评审纪律 + 文档约定。** 被否：这正是现状，且现状已经出过错。
- **运行时警告而非异常。** 被否：警告会被忽略，而错误的总量一旦进了给管理层的报告就无法追回。
- **给数值加单位后缀（`vol_usd_spot`）的命名约定。** 被否：命名不能阻止 `sum()`，
  且一旦进入 pandas / SQL 聚合就完全失效。

## Consequences

- 聚合代码必须显式解包 `ScopedValue`，比直接相加啰嗦。这是刻意的成本。
- 未验证值在 `safe_sum()` 中被跳过而非当作 0，结果被标记为未验证——
  部分覆盖的合计不得被呈现为完整合计。
