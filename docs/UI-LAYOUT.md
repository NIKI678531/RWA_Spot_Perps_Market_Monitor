# 版式与信息架构

> `DESIGN.md` 是权威视觉规范，**本文件不修改它**。本文只规定这个产品的版式落地方式。
> 图表规范见 `DATAVIZ.md`；需求编号与验收标准见 `REQUIREMENTS-R1.md`。
> 版本 R1 · 2026-08-26。信息架构按业务决策闭环重组，v2.0 的问候式首页已废弃。

## 0. 版式要回答的问题

页面结构服从决策闭环 **发现 → 验证 → 解释 → 行动 → 复盘**，不服从数据源结构。
每个页面在开工前先回答：它承担闭环里的哪一步？回答不了就不该存在。

| 层级 | 回答什么 | 不承担什么 |
|:--|:--|:--|
| 决策首页 | 发生了什么 · 是否可信 · 业务影响 · 是否要行动 | 不展示检测器参数或长表 |
| 专题页 | 主题 / 场所 / 永续 / 发行商的结构与变化 | 不替代单底层的完整证据链 |
| Underlying 360 | 单一底层的全部证据与覆盖关系 | 不做跨底层总量汇总 |
| 异常详情 | 为何触发 · 证据 · 反证 · owner · 动作 · 结论 | 不隐藏未通过发布条件的原因 |

## 1. 全局壳

```
┌───────────────────────────────────────────────────────────────────┐
│ ░ 液态背景层 (z:0, pointer-events:none) + background-overlay ░     │
│ ┌────┬──────────────────────────────────────────────────────────┐ │
│ │    │ 顶栏 56px：统一搜索 · scope · edition · 时间窗 ·          │ │
│ │ 导  │           语言 · 明暗 · 用户菜单                          │ │
│ │ 航  ├─────────────────────────────────────────────────────────┤ │
│ │ 侧  │ 状态条：scope / edition / as_of / 数据年龄 / 源覆盖 /     │ │
│ │ 栏  │        验证状态 / 下次刷新                                │ │
│ │ 200 │─────────────────────────────────────────────────────────│ │
│ │     │      内容区   max-width 1440   padding 32 / 40          │ │
│ └─────┴─────────────────────────────────────────────────────────┘ │
└───────────────────────────────────────────────────────────────────┘
```

- **左侧 rail 200px，常驻展开**，图标 + 文字标签同时可见，没有折叠态。
  它推挤内容区（`shell__main` 的 `margin-left` 跟随同一个 `--rail-width`），不浮在内容之上。
  代价是宽表与时序图少 128px 横向空间；换来的是导航目的地始终可读，
  不需要先把指针移过去才知道有哪些页面。
- **分组用间距不用分割线**（`DESIGN.md` 原则 2 留白优先）：组间 `spacing.lg` (24px)，组内 `spacing.sm` (8px)。
- 激活态用**左侧 3px 渐变竖条**，不用整块底色（`DESIGN.md` Shapes 节：高光用描边不用填充）。
- **搜索在顶栏，不在首页正中**。它是工具，不是产品主张；命中结果直接进入对应实体页并标示实体类型
  （underlying / asset / issuer / venue / pair / perp contract / theme）。
- **状态条每页常驻**，不是首页专属。任何一屏被截图贴进 PPT 时，读者都能知道这是哪个版本、
  数据截到什么时候、有没有未验证项。

### 1.1 导航分组

按决策闭环分四组，P0 页面置顶：

| 组 | 页面 | 优先级 |
|:--|:--|:--|
| 决策 | 决策首页 · 异常雷达 | P0 |
| 研究 | 主题需求 · 发行候选 | P0 |
| 市场结构 | 现货规模 · 场所 · 永续 | P1（复用重整） |
| 治理 | 数据质量 · 报告与复盘 | P0 |

**Underlying 360 不在导航中**，只能从任意列表、图表或告警下钻进入。
它是一个实体详情页，不是一个目的地；放进导航会逼用户先选实体再看内容。

发行商在 R1 嵌入主题 / Underlying 360 / 场所三个页面；独立竞争页是 R2。

## 2. 五个版式模板

所有页面套用其中之一。每页各写各的排版必然导致不一致。

### T1 决策 — 决策首页

`DESIGN.md` 原则 7「首屏叙事」的落地：**第一屏是一句业务结论，不是问候，也不是图表墙**。
v2.0 的「下午好 + 搜索框 + 向下看数据」被废弃——它把首屏让给了输入，
而首屏应该输出：今天最重要的变化是什么、可不可信、要不要动。

```
            ░ 液态背景 + background-overlay ░

    ┌ 状态条 ────────────────────────────────────────────┐
    │ CORE+ADJACENT+SYNTHETIC · Live · 09:41 · 数据 12min │  label-sm
    │ 8/9 源已验证 · 下次刷新 10:00                        │
    └────────────────────────────────────────────────────┘

    Pre-IPO 需求今日集中放量，跨 3 个场所印证，              display-hero 32-36px
    建议今日内认领并进入研究任务。                            事实→意义→可信度→动作
    3 条 high 待认领 · 1 项指标未验证                        body-lg / text-secondary

    ┌────────┬────────┬────────┬────────┐                四问卡（≥1440 四列）
    │ Q1 成交│ Q2 升温│ Q3 新品│ Q4 可发│  答案 / 变化 / 证据
    │ 最大   │ 最快   │ 表现   │ 行候选 │  反证 / 信心 / 单个 CTA
    └────────┴────────┴────────┴────────┘
    ┌────────────────────┬────────────────────┐
    │ Top 机会（≤3）      │ Top 风险（≤3）      │  含 owner 与待办状态
    └────────────────────┴────────────────────┘
    ┌───────┬───────┬───────╎───────┬───────┐         五类 KPI
    │现货市值│现货成交│DEX流动│永续成交│永续 OI│         ╎ = 口径分隔
    └───────┴───────┴───────╎───────┴───────┘         （虚线：不可加总）
    ┌──────────────────┬──────────────────┐
    │ 成交 Treemap      │ OI Treemap        │  并排但**永不合计**
    ├──────────────────┴──────────────────┤
    │ 主题份额 · 场所结构 · 基线趋势 · 证据热力图 │
    └─────────────────────────────────────┘
    最近告警 · 待认领 · 数据缺口 · 常用底层 · 报告入口     快速下钻
```

信息顺序是硬规范，桌面与平板一致：**状态条 → 一句话摘要 → 四问卡 → 机会/风险 → 五 KPI →
证据图组 → 快速下钻**。

- **一句话摘要**结构固定为 `事实 → 意义 → 可信度 → 建议动作`，由结构化的已验证事实模板化生成，
  不做自由发挥。依赖项未验证时**不输出肯定结论**，改为「当前无法形成可靠结论」并给出原因。
- **四问卡**每张必须同时具备：答案、变化、证据、**反证**、信心、一个 CTA。
  少了反证的卡片不上线——单边论证会让人停止阅读。
- **首页只展示 `high` / `critical` 且证据完整的告警。** 横截面异常可即时出现，
  但必须标注「同组现状异常」；时序异常必须满足同 session ≥14 样本、绝对量门槛与连续 2 次确认。
- **五类 KPI 物理分开，永不出现总计。** KPI 带按 STOCK / FLOW 分组，组间插入 `spacing.lg` 的空隙
  与一条虚线，**视觉上就不成立的加法，代码里也加不了**。
- 折叠线以下的内容随滚动 stagger 入场（`60ms × i`，上限 600ms）。

### T2 榜单 — 现货规模 · 场所 · 永续 · 主题需求

```
┌─────────────────────────────────────────────────────┐
│ 页面标题 h1        │  筛选条 chip 组（tier/时间/口径）│
├─────────────────────────────────────────────────────┤
│          主图（Hero，高度 360px）                    │
├─────────────────────────────────────────────────────┤
│  明细表：raw / adjusted 双列并排，数字 tnum          │
│  未验证行渲染灰色斜纹占位                            │
└─────────────────────────────────────────────────────┘
```

- 一屏一焦点的焦点是**主图**（`DESIGN.md` 原则 1 明确允许主图表作为 Hero）。
- 筛选条用 chip 不用下拉，选中态即 `badge-*` 的激活样式；筛选状态写入 URL。
- 表格 raw / adjusted **必须同屏并排**，不得用 tab 切换——tab 会让人只看到其中一个。
  默认业务排序用 adjusted，但 raw 不得隐藏。
- 每行的实体名可点击下钻到 Underlying 360，**保留当前筛选上下文**。

```
│         底层市场 session · 映射置信度                │
├──────────────────┬──────────────────────────────────┤
│ 【现货口径】     │ 【永续口径】                      │
│ ┌──────┬──────┐  │ ┌──────┬──────┐                  │
│ │ 市值 │ 成交 │  │ │ 成交 │  OI  │   + DEX 流动性   │
│ └──────┴──────┘  │ └──────┴──────┘                  │
│  图：市值/成交   │  图：成交/OI                     │
├──────────────────┴──────────────────────────────────┤

├─────────────────────────────────────────────────────┤
│  场所与流动性：份额 · 集中度 · 跨所一致性            │
├─────────────────────────────────────────────────────┤
│  趋势与基线：当前值 · 同 session 中位数 · MAD 阈值 · n │
├─────────────────────────────────────────────────────┤
│  告警与证据（含反证与处理状态）                      │
├─────────────────────────────────────────────────────┤
│  产品覆盖与动作：已覆盖 / 候选 / 空白 / 竞品先发     │
└─────────────────────────────────────────────────────┘
```

**按口径分栏是硬约束的版式化**：不同 `MetricScope` 物理上分在不同的卡片容器里，
中间有明确的分隔与各自的标题。跨口径相加在版面上就不成立，比在代码里抛异常早一步。

- 一个 underlying 对多个 asset：表里用实体 ID 关联，**不用 ticker 代替实体**。
- `source_underlying_type`（交易所原始标签）与 `analysis_group`（我方分组）**并列显示**，不覆盖。
- 冷启动实体的趋势图**不画阈值线、不写「已触发」结论**，只标注「样本不足，仅记录」。
- 「推荐动作」永远只是推荐：发行需进入独立评估门，页面上不得出现审批语义。

### T4 队列 — 异常雷达 · 数据质量

v2.0 的时间轴流水升级为**工作队列**。告警是可认领、可推进、可复盘的业务对象，
时间轴只是它的一种排序方式。

```
┌ 队列摘要：待认领 4 · 处理中 2 · 待复核 1 · 已关闭 12 · 误报 3 ┐
│           按严重度与超时着色，不用分数代替严重度              │
├──────────────────────────────┬──────────────────────┤
│ 筛选：状态 / 严重度 / 族 /    │                      │
│      底层·主题 / scope /      │   证据与处理抽屉      │
│      session / owner / 时间 / │   （选中时滑入）      │
│      数据质量                 │                      │
├──────────────────────────────┤   事实   ...         │
│ ○ CRITICAL · 待认领 · SLA 4h │   意义   ...         │
│   SPCXB 沉睡唤醒 T2          │   证据   原值/基线/n  │
│   bStocks · Pre-IPO · @未分派 │         session/规则  │
│ ○ HIGH · 处理中 · @lin       │   反证   单一场所 97% │
│   LBank 份额 -6.2pp  T6      │   置信度 连续确认 2/2 │
│ ○ MEDIUM · 待复核            │   时间线 / 相邻异常   │
│   ...                        │   ┌ 动作区 ────────┐ │
│                              │   │认领 转派 备注  │ │
│                              │   │确认 误报 搁置  │ │
│                              │   │建任务 关闭     │ │
└──────────────────────────────┴───┴────────────────┴─┘
```

- 默认视图是 **open + 待行动**，不是「全部按时间倒序」。队列的默认值决定了谁会被看见。
- **证据字段一个都不能省**：原值、基线（或对照组）、`robust_z`、样本量、`market_session`、
  规则名、确认次数。缺 evidence 的告警不可发布，抽屉里也不该有它。
- 横截面族抽屉显示的是**对照组**而非基线（组名、组内中位数、组内样本数），
  文案写「同组现状异常」；时序族才写「相对历史基线升温」。两族文案不得混用。
- 每个处理动作写审计：谁、什么时候、从什么状态改到什么状态、理由。
- **关闭前必须给出复盘**（最终结论、是否真实、影响决策、误报原因、阈值建议）
  或标准化的「不处理原因」。没有出口理由的关闭按钮不要做。
- 数据质量页复用同一模板：源健康 / 实体覆盖 / 质量差异 / 验证状态 / 基线健康五个区，
  缺口进同一种可分派队列（owner、SLA、修复状态）。

## 4. 状态

每个数据区域必须实现下列状态，缺一不可：

| 态 | 表现 | 允许的业务行为 |
|:--|:--|:--|
| 加载 | 骨架屏 + shimmer，形状要暗示即将出现的版式。**禁止 spinner** | 筛选可保留；**不得把旧值当新值显示** |
| 已验证 | 正常渲染 + 观测时间与来源 | 可进入结论与告警 |
| 部分验证 | 琥珀提示 + 缺失范围说明 | 可展示有限结论，但必须降低置信度表述 |
| 未验证 | 灰色斜纹占位 + 「未验证」+ 原因 + 最后成功时间。**绝不显示 0** | 不可当 0，不主动推送 |
| 过期 | 显示最后成功时间与数据年龄 | 超过阈值不生成新的管理层结论 |
| 空 | 图标 + 「已验证为无记录 / 无活动」+ 一个可执行动作 | 可作为真实零陈述 |
| 错误 | 局部错误 + 重试 + trace/reference id | **局部失败不阻断其它模块** |
| 无权限 | 说明无权限与申请入口 | **不得泄露记录是否存在** |

「空」「未验证」「过期」是三个不同的态，不得合并：
空是「观测到了，确实没有」，未验证是「没能观测到」，过期是「观测到过，但太久了」。

## 5. 响应式

断点沿用 `DESIGN.md`：`768 / 1024 / 1440`。

| 断点 | 变化 |
|:--|:--|
| ≥1440 | 四问卡 4 列；双 treemap 并排；机会/风险与 KPI 同屏可扫读；T3 双口径栏并排 |
| 1024–1440 | 四问卡 2×2；证据图组 2 列或单列，**信息顺序不变**；T3 双口径栏保持并排 |
| 768–1024 | 单列；rail 收为顶部抽屉；状态条可横向滚动；T3 双口径栏上下堆叠，**分隔与口径标题必须保留** |
| <768 | 表格转卡片列表；主图高度降至 240px；首屏保留摘要、最高优先级机会与数据健康三块 |

任何断点下，口径分组的视觉分隔都不得被折叠掉——这是版式承担的正确性职责，不是装饰。

移动端定位是**查阅与处理高优先级事项**（看摘要、认领、写备注），不承载复杂多图比较。

## 6. 可访问性与 i18n

- 所有可点击元素具备 `default / hover / active / disabled / focus-visible`；无意义循环动画一律不做。
- 图表提供键盘焦点、文本摘要、「查看数据表」入口、足够对比度与非颜色编码（`DATAVIZ.md` §5）。
- 表格数字右对齐且 `tabular-nums`，名称左对齐；时间统一显示 HKT 并可查看源时区。
- 所有用户可见文案走 `t(key, '中文 fallback')`，zh / en / ko / zh-TW 四语种齐备（`DESIGN.md` Do's）。
  R1 主界面为中文，机制保留。
- 数字格式随语言切换，但**金额缩写单位保持 K / M / B 不本地化**——
  中文语境下的「亿」与英文 `B` 换算关系不同，混用会直接产生读数错误。
